# AGENTS.md

Вход для любого кодового агента (Codex, Claude Code и других). Правила проекта
не дублируются здесь, а лежат в одном месте:

- [CLAUDE.md](CLAUDE.md) — устройство, команды и инварианты, которые нельзя ломать.
  Обязателен к прочтению целиком до первой правки.
- [docs/CONTRACTS.md](docs/CONTRACTS.md) — форматы данных и гарантии.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — карта модулей.
- [docs/tickets/](docs/tickets/) — текущие задания.

## Если ты исполнитель тикета

Тикет задаёт, что должно быть верно в конце, и таблицу приёмки. Контракт тикетом
не меняется: расхождение с `docs/CONTRACTS.md` — эскалация тех-лиду, а не правка
чужого модуля. Сдача — вывод команд из таблицы приёмки, а не «всё работает».

## Если ты оценщик

Codex проверяет дифф против тикета: `sh scripts/codex-review.sh docs/tickets/<тикет>.md`.
Замечание без файла и строки не пишется; P0/P1 — только то, что сломает работу
или расходится с тикетом.

## Коротко о самом важном

- `corpus/v1/docs` и `eval/golden/` не менять; `eval/golden/holdout.yml` не читать.
- SQL только в `db.py`; цитаты, URL и ограничения — из кода и БД, не из ответа модели.
- Реальные вызовы Claude в тестах только под маркером `live`; обычный прогон их не делает.
- Падающий тест — результат для отчёта, а не повод его переписать.

Перед сдачей: `ruff check backend` и `pytest backend/tests`.
В Claude Code первые два правила и проверки ещё и закреплены хуками,
см. [.claude/settings.json](.claude/settings.json).
