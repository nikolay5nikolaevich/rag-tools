# Формат проверочного набора

Файлы: `A-facts.yml`, `B-synthesis.yml`, `C-reliability.yml`, `D-domain.yml`, `E-refusal.yml`,
`F-metadata.yml`, `holdout.yml`. Владелец разметки — тех-лид (T-03), исполнители её не правят:
найденная ошибка идёт в отчёт тикета.

```yaml
- id: A-01
  category: A                      # A..F, см. спеку раздел 8
  question: "Сколько касаний и какая пауза в базовом правиле follow-up после события?"
  answerable: true                 # false = обязателен отказ
  expected_source_ids:             # совпадение считается на уровне ИСТОЧНИКА, не чанка
    - trade-show-and-conference-lead-follow-up-secrets-featuring-harri
  must_contain: ["8", "12 недель"] # что обязано быть в ответе
  must_not_contain: []             # чего быть не должно (типовая выдумка)
  expected_limitations: []         # ожидаемые kind из контракта §7
  notes: "Harriet Mellor; цифры — эвристика спикера, не измеренные данные"
  holdout: false
```

## Правила

1. `expected_source_ids` — идентификаторы по контракту §2. Проверять по `corpus/v1/manifest.json`,
   а не писать по памяти.
2. Пропорции по спеке: ~40% A (факт, один источник), ~25% B (синтез), ~15% C (конфликт
   и достоверность), ~20% E (обязательный отказ). Долю отказов не занижать — это ключевая витрина.
3. Всего 30–35 вопросов, из них **10 в `holdout.yml`**. Holdout открывается один раз, на T-30.
   Загрузка holdout без явного флага запрещена и покрыта тестом в T-13.
4. Каждый вопрос привязан к факту, реально присутствующему в корпусе, — проверено чтением файла,
   а не правдоподобием.
5. При n≈35 разница между вариантами меньше ~15 п.п. неотличима от шума. Это указывается
   в каждом отчёте прямо.
