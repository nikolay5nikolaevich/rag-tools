## Ограничения

- Прогон неполный: 30 из 132 вызовов модели не состоялись (CLI не ответил). Метрики посчитаны по выжившим вопросам, а они не случайная выборка — это промежуточные числа, а не результат сравнения.
- При n≈35 разница между вариантами меньше ~15 п.п. неотличима от шума (golden set рассчитан на порядок величины, не на статистическую значимость).
- Повторов больше одного не делалось: разброс между прогонами не измерен, и различия между вариантами нельзя отделить от случайности одного прогона.
- Подтверждённость утверждений не измерена: судья не откалиброван по ручной разметке. Это не ноль ошибок, а отсутствие измерения.
- Замер кэша и служебной части вызова не выполнен: стоимость в отчёте — только расчёт по usage бэкенда, без разделения на наш промпт и служебные токены.
- Стоимость расчётная. Генерация идёт по подписке через Claude Code CLI: ни расчёт по прайсу, ни значение бэкенда не равны фактическому списанию, а служебная часть вызова входит в `input_tokens` и отделена только нижней оценкой.
- Для cli-бэкенда не заявляется управление temperature: соответствующего флага у headless-режима нет, детерминизм ответов не предполагается.
- Лучший вариант (`fts`) опережает следующий (`rag`) на 0 п.п. — меньше порога различимости при таком n. Выигрыш RAG на этом наборе не доказан.
