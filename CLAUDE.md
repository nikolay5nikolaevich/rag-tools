# Работа с ErgoVault RAG

RAG над фиксированным исследовательским корпусом: 43 заметки о международных выставках.
Язык документации, комментариев и интерфейса — русский.

## С чего начать

1. `docs/ARCHITECTURE.md` — карта модулей, запуск и очередь задач.
2. `docs/CONTRACTS.md` — форматы данных и гарантии, включая требования к будущему API.
3. `docs/tickets/` — только действующие задания.

## Устройство

- Подготовка: `indexing.prepare` → `db.upgrade` → `ingest.ingest_corpus` →
  `db.load_index` → `indexing.embed` → `embeddings` и `db`.
- Поиск: `search.search` → полнотекстовый SQL и/или эмбеддинг вопроса → RRF.
- `eval.evaluate` вызывает тот же поиск, записывает прогоны и метрики.
- `cli.py` содержит только команды. Прикладные функции не импортируют CLI/Typer.
- `llm/` содержит доступ к Claude через CLI и API.
- Ответ: `answering.answer` → `search` → промпт из `prompts/` → `llm` → проверка
  номеров и цитат → ограничения из метаданных. `answering.answer_hits` — вход для оценки.
- `api.py` — HTTP-слой: разбор запроса, вызов `search`/`answering`, `query_log`, коды ошибок §8.
  Фронтенд ходит в живой API; моки msw включаются отдельно (`npm run dev:mock`).

## Запуск

```bash
pip install -e "backend[dev,embed]"
docker compose up -d db
ev prepare                         # вся подготовка базы
ev eval retrieval --mode hybrid --k 5
pytest backend/tests
ruff check backend
uvicorn ergovault.api:app --port 8000   # API для фронтенда
```

Сохраняются команды отдельных этапов: `ev ingest --report`, `ev db upgrade`,
`ev db load [каталог]`, `ev embed --batch 32`, `ev embed --no-write-db`.
Для полной подготовки нужны установленная локальная модель и живой PostgreSQL.
Ключ Claude для индексации не нужен. Запуск фронтенда — `npm run dev` из `frontend/`
(dev-сервер проксирует `/api` и `/healthz` на `:8000`); браузерные сценарии — `npx playwright test`.

## Неизменяемые при обычном рефакторинге правила

- Исходный vault не менять; входные документы `corpus/v1/docs` не переписывать.
- Сохранять `make_source_id`, идентификаторы чанков, форматы JSONL и схему БД.
- Отсутствующие метаданные — `None`; атрибуция только по словарям, без догадок.
- Оригинал видео и его пересказ не считать независимыми подтверждениями;
  сохранять `derived_of`, `speaker_org`, `reliability_note`.
- SQL только в `db.py`. Фильтровать public/pilot в SQL обеих ветвей поиска.
- Сохранять два tsvector (russian/simple), размерность вектора и компоненты RRF.
- Загружать модель лениво, переиспользовать между вопросами; кэш сохранять до записи в БД.
- Не вводить ORM, систему плагинов или новую инфраструктуру без конкретной необходимости.
- При реализации ответов URL брать из БД, цитаты проверять кодом, ограничения вычислять
  из метаданных. Модель не является источником фактов о корпусе.
- Holdout не читать без явного `--include-holdout`; он предназначен для финального эксперимента.
- Версии корпуса, промпта, режима поиска и модели сохранять в результатах измерений.
- Не выдавать отсутствие измерений за нулевую ошибку; оговорку о малой выборке сохранять.
- При переносе кода проверять прежние инварианты, а не переписывать тесты под новый результат.
