# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

RAG-сервис над замороженным корпусом исследования международных выставок (43 заметки,
~56 тыс. слов). Вопрос → поиск фрагментов → ответ Claude с дословными цитатами, ссылками
на первоисточники и блоком «Ограничения». Отказ «данных нет» — полноценный ответ, а не сбой.

Язык проекта — русский: документация, промпты, комментарии, сообщения CLI и UI.

## Порядок чтения перед любой задачей

1. `docs/CONTRACTS.md` — **нормативен целиком**. Единственный источник правды.
2. `docs/PLAN.md` — волны, зависимости, реестр тикетов.
3. `docs/tickets/T-XX-*.md` — бриф конкретной задачи.
4. `ErgoVault-RAG — описание проекта.md` — спека: контекст, находки, сценарии.

Расхождение кода с контрактом — баг кода, а не устаревший контракт. Контракт правит только
тех-лид; из тикета его менять нельзя, расхождение эскалируется.

## Жёсткие правила

- **Исходный vault не изменяется никогда.** Работаем только с `corpus/v1/`, снапшот читается
  скриптом, оригиналы не трогаются.
- **Границы пакетов не пересекаются** (`CONTRACTS.md` §0). Нужен чужой код — импортируй его
  публичный интерфейс. Интерфейса нет — это блокер, эскалируй, а не дописывай чужой пакет.
- **Пустое значение лучше выдуманного.** Отсутствующие метаданные → `None` + строка в отчёте.
  Никакого fuzzy-матчинга, никаких догадок по правдоподобию.
- **Не подгонять метрику под красивую цифру.** Сначала честный расчёт, потом обсуждение.
- Тесты пишутся на инварианты слоя, а не на happy path.

## Архитектура: два конвейера

**Офлайн (редко, руками).** `corpus/v1/*.md` → `ingest` (парсинг + чанкинг + атрибуция) →
`corpus/v1/index/*.jsonl` → `index` (COPY в Postgres) → `embed` (BGE-m3 локально) →
`chunks.embedding`. Ingest — чистая функция от файлов: без сети, без БД, идемпотентен побайтово.

**Онлайн (на каждый запрос).** вопрос → `retrieval` (fts | vector | hybrid) → `list[Hit]` →
`generation` (промпт → Claude → **валидация кодом**) → `AnswerPayload` → `api` (+ `query_log`) →
`frontend`.

Слои встречаются только в Postgres и в моделях `ergovault/models.py`.

| Слой | Пакет | Тикет |
|---|---|---|
| Парсинг корпуса → Source/Chunk | `ergovault.ingest` | T-10 |
| Хранение, миграции, FTS | `ergovault.index` | T-11 |
| Эмбеддинги | `ergovault.embed` | T-12 |
| Стратегии поиска | `ergovault.retrieval` | T-20 |
| Промпт, генерация, валидация | `ergovault.generation` | T-21 |
| HTTP API, журнал | `ergovault.api` | T-22 |
| Метрики, судья, эксперимент | `ergovault.eval` | T-13 / T-23 / T-30 |
| UI | `frontend/` | T-14 |

## Решения, которые нельзя переизобрести

**Модель не является источником фактов о корпусе.** Она пишет текст и ставит `[n]` — всё
остальное делает код: проверяет соответствие `[n]` ↔ `Citation`, дословность цитаты,
подставляет URL из БД, вычисляет `limitations` из метаданных. Поэтому доля выдуманных URL
нулевая *по построению*, а не по измерению. Ограничения не переносятся в промпт — это
архитектурное решение (`PROMPTS.md` §1). В промпт не попадают `url`, `speaker_org`, `stance`,
`reliability_note`, `derived`.

**Файл ≠ источник.** В корпусе 13 видео и 13 пересказов тех же видео (`video-theses`).
Наивно они выглядят как 26 независимых подтверждений. Схлопывание — по `speaker_org`, для
производных — по `derived_of` (13 связей в `corpus/v1/derived_map.yml`, выверены вручную;
frontmatter `source_video` заполнен лишь у одной заметки из тринадцати, полагаться на него
нельзя). Материалов с участием RusGlobalExport — пять, а не четыре.

**Два tsvector обязательны.** `russian` даёт морфологию, `simple` спасает GITEX / HubSpot /
Baselworld / Organic & Natural. Корпус русский с английскими именами собственными — чистый
вектор на них систематически промахивается, поэтому гибрид здесь по существу, а не для галочки.
RRF: `score = Σ 1/(60 + rank_i)`, `components` в `Hit` заполняется всегда — без него не отладить,
почему имя собственное не нашлось.

**`make_source_id()` менять нельзя** (`models.py`, контракт §2). Id попадает в БД, eval-разметку
и ссылки UI; смена алгоритма обесценивает всю накопленную ручную разметку. Папка входит в id
намеренно: одноимённые файлы лежат в `Источники видео/` и `Тезисы видео/`.

**Профиль фильтруется в SQL**, не в Python (`WHERE s.visibility = ANY(...)`). Утечка
pilot-контента в public — дефект уровня «стоп-релиз»: `raw/` это ASR-расшифровки чужих видео.
Параметр запроса `profile` разрешён только при `EV_PROFILE=pilot`.

**Заглушки → `None`.** В корпусе `url` часто заполнен текстом «не указана (Telegram-стрим)»,
«не предоставлен». Значение, начинающееся с «не указан», «не предоставл», «нет ссылки»,
«unknown», или не начинающееся с `http` — это `None`, иначе UI покажет ссылку-обманку.
То же для `duration`, `published`, `channel`.

**Индексация обязана работать без единого внешнего API-ключа.** Эмбеддинги локальные
(`BAAI/bge-m3`, 1024 измерения). Ключ нужен только для генерации и судьи.

**Судья — другая модель и другой промпт**, чем генератор (`claude-sonnet-5` против
`claude-opus-5`): совпадающий судья оценивает сам себя. Цифра подтверждённости без измеренного
согласия судьи с ручной разметкой (40–50 пар, Cohen's kappa) в отчёт не идёт.

**Long-context baseline не срезать** (T-30, вариант 4). Корпус ~70–90 тыс. токенов влезает
в окно целиком; сравнение с prompt caching обязательно. Вывод «RAG оправдан стоимостью
и латентностью, а не точностью» — допустимый результат, идёт в отчёт как есть.

**Holdout (10 вопросов) открывается один раз, на T-30.** Загрузка без явного
`--include-holdout` запрещена и покрыта тестом — это защита от самообмана.

**При n≈35 разница меньше ~15 п.п. неотличима от шума.** Оговорка обязательна в каждом отчёте;
отчёт без неё не принимается.

## Версионирование

`corpus_version`, `prompt_version`, `retrieval_mode`, `model` пишутся в каждую строку
`query_log` и в каждый прогон eval. Результат, не привязанный к этим четырём, недействителен.
Промпты лежат файлами (`generation/prompts/p1_*.md`), не строками в коде; правка промпта —
инкремент `EV_PROMPT_VERSION`, метрики между версиями несравнимы.

## Чего не делать

- Не вводить ORM: psycopg3 + явный SQL. Схема маленькая.
- Не тащить Alembic: пронумерованные SQL-файлы, их читает человек.
- Не добавлять переранжирование в T-20, пока разбор промахов не покажет, что оно нужно.
- Не «улучшать» текст корпуса: не переписывать, не исправлять опечатки, не дополнять.
- Не показывать процент уверенности в UI — ни в каком виде.
- Не звать облачные эмбеддинг-API.
