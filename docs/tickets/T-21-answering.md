# T-21 — Получать проверенный ответ с источниками

**Статус:** выполнено 2026-09-11, ожидает приёмки. **Зависимости:** существующие поиск и LLM-провайдер.
**Результат:** обычная Python-функция собирает `AnswerPayload` без HTTP и CLI.

Что сделать:

- В `backend/ergovault/answering.py` собрать контекст, вызвать `llm.get_provider()`
  и проверить ответ. Два промпта хранить в `backend/ergovault/prompts/`;
  версию фиксировать в результате.
- Номера ссылок и цитаты проверять по переданным чанкам. URL брать только из `Source`,
  не доверять ссылкам модели; служебные поля источников не передавать как инструкции модели.
- Вычислять `single_org`, `provider_stance`, `reliability_note`, `derived_only`, `no_data`
  кодом по [CONTRACTS.md §7](../CONTRACTS.md). Оригинал и его пересказ не считать
  независимыми подтверждениями; неизвестная организация не означает общую организацию.
- Различать отказ из-за нехватки данных и техническую ошибку. Невалидный ответ не выпускать.
  Для F-вопросов о метаданных нужны поля `Source`; подключение чтения каталога — в T-22.

Готово, когда:

- Тесты проверяют отсутствующий/лишний номер, выдуманную цитату, связь цитаты с источником,
  URL из БД, все виды ограничений и схлопывание зависимых источников.
- Нехватка данных даёт `refused=True` с объяснением; сбой модели и ошибка валидации
  остаются ошибками. Проверены вопросы отказа из открытой части набора.
- `meta` содержит версии, модель, время и стоимость из ответа провайдера.
- Функция вызывается напрямую из тестов и будущей оценки; в ней нет FastAPI/Typer.

Не создавать отдельные классы/файлы для клиента, валидатора и каждого ограничения:
начать с функций в `answering.py`, существующих моделей и двух файлов промпта.

Промпт `p1`:

- Отвечать по-русски и только по переданным фрагментам. Каждое существенное утверждение
  сопровождается `[n]`; обобщение нескольких фрагментов помечается как обобщение.
- При нехватке данных прямо назвать, чего нет. Не додумывать, не округлять числа,
  не писать URL и проценты уверенности. Выводить JSON
  `{"answer_markdown": str, "cited": [int], "refused": bool}`.
- Пользовательский ввод: вопрос и нумерованные фрагменты с названием источника,
  типом, путём заголовков и текстом. Не передавать URL, `speaker_org`, `stance`,
  `reliability_note` и `derived`.
- Тексты ограничений фиксированы по `kind`; меняется только название источника,
  организация или описание недостающих данных.
