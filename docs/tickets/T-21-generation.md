# T-21 — Генерация ответа: цитаты, валидация, программные ограничения

**Пакет:** `backend/ergovault/generation/`. **Зависит от:** T-04 (промпты), T-15 (провайдер), T-20.
**Читать:** `docs/CONTRACTS.md` §7 — он нормативен целиком, `docs/PROMPTS.md`.

## Задача

Из вопроса и найденных фрагментов собрать `AnswerPayload`, где всё проверяемое проверено кодом.

1. `prompt.py` — сборка контекста: фрагменты нумеруются, модель ссылается на номера.
   **URL модели не передаются вообще** — она физически не может их выдумать. Версия промпта
   в `EV_PROMPT_VERSION`, промпт лежит файлом, а не в коде строкой.
2. `client.py` — вызов модели **только через `ergovault.llm.LLMProvider` (T-15)**: по умолчанию
   бэкенд `cli`, то есть по подписке, без платного ключа. Прямой Anthropic SDK здесь запрещён.
   Токены, латентность и `billed_cost_usd` из `LLMResponse` кладутся в `meta`.
3. `validate.py` — программные гарантии §7: соответствие `[n]` ↔ Citation, дословность цитаты,
   URL только из БД. Нарушение — не «предупреждение в логе», а ошибка сборки ответа: битый
   ответ не отдаётся наружу.
4. `limitations.py` — **ограничения вычисляются кодом**, не моделью: `single_org`,
   `provider_stance`, `reliability_note`, `derived_only`, `no_data`. Схлопывание подтверждений
   по `speaker_org`, для `derived` — по `derived_of`.
5. Отказ — первоклассный сценарий: если фрагменты не покрывают вопрос, `refused=True` и текст
   о том, каких данных не хватает. Придумывать правдоподобное запрещено.

## Тесты

- вопрос из категории E golden set → `refused=True`;
- ответ, где все цитаты из РусГлобалЭкспорт → `single_org` + `provider_stance`;
- ответ, где цитаты — `video-source` и его же `video-theses` → это **одно** подтверждение;
- подмена цитаты в ответе модели (мок) → валидатор падает, наружу ответ не уходит;
- ни в одном тесте модель не получает URL на вход.

## Границы

Не трогать ретриверы и API. Не переносить вычисление ограничений в промпт — это архитектурное
решение, а не деталь реализации.
