# T-32 — Подготовить проект к демонстрации

**Статус:** README написан, запуск воспроизведён в чистой копии 14.09.2026; ждёт
завершения T-30 — после полного прогона обновить раздел README «Чем это проверено».
**Зависимости:** T-22 и T-30.
**Результат:** другой человек запускает демо и понимает, что оно умеет и чем это проверено.

Что сделать:

- Написать корневой `README.md`: назначение, требования, запуск БД, `ev prepare`, API
  и фронта, доступ к Claude, ссылка на результаты. Индексация работает без облачного ключа;
  для ответов нужна авторизация CLI или API-ключ — это указать прямо.
- Использовать `eval/reports/final-comparison.md` как единственный итоговый отчёт;
  не копировать таблицы в отдельные REPORT.md и error-analysis.md.
- Проверить четыре сценария: подготовка к выставке, сопоставление ошибок разных источников,
  проверка доказательств окупаемости, вопрос о цене вне базы. Показывать реальные
  ограничения и ошибки.
- В README использовать формулировку: «Корпус — результат моего выполненного коммерческого
  исследования выставок. RAG-сервис над ним — самостоятельное продолжение, построенное
  для демонстрации. Статус пилота появится, если заказчик начнёт им пользоваться».

Готово, когда:

- Запуск по инструкции воспроизведён в чистом окружении; нет скрытых шагов и моков
  вместо API. Результат проверки записан в README.
- Демо открывается на публичном профиле, исходный vault и закрытые транскрипты не публикуются.
- README ведёт к реальным результатам и разобранным ошибкам; малое число отзывов
  представлено конкретными случаями, а не убедительно выглядящими процентами.

Публикация на хостинге не требуется для локального демо; адрес и способ размещения —
отдельное решение при необходимости. Не добавлять инфраструктуру ради оформления портфолио.
