# T-12 — Эмбеддинги: локальная модель, батч-индексация

**Пакет:** `backend/ergovault/embed/`.
**Читать перед стартом:** `docs/CONTRACTS.md` §5 (размерность), §9 (конфиг).
**Зависит от:** T-00; для записи в базу — T-11 (до его готовности писать в `.npy` + JSONL).

## Задача

Векторизовать чанки локальной моделью, без внешних API-ключей — репозиторий должен
индексироваться у любого рецензента.

## Что сделать

1. `ergovault/embed/model.py` — обёртка над `sentence-transformers`, модель `BAAI/bge-m3`
   (1024 измерения, мультиязычная, держит смесь русского с английскими терминами — ровно наш
   корпус). Модель задаётся `EV_EMBED_MODEL`, размерность проверяется на старте и при
   несовпадении с колонкой `vector(1024)` падает с внятной ошибкой, а не молча.
2. Префиксы запроса и документа применять по требованиям модели (для BGE-m3 их нет, для e5 —
   `query:`/`passage:`); ветка выбирается по имени модели, а не флагом.
3. `ev embed [--batch 32] [--force]` — считает эмбеддинги для чанков без вектора,
   пишет через `repository.update_embeddings(...)`. Прогресс и итоговое время в stdout.
4. Кэш: `corpus/v1/index/embeddings.<model>.npy` + `chunk_ids.json`. Повторный прогон на том же
   корпусе не пересчитывает ничего. Корпус маленький, но переиндексация будет частой.
5. Тест: 20 фикстурных чанков → векторы нужной размерности, косинус между «follow-up после
   выставки» и релевантным чанком выше, чем со случайным.

## Границы

- Не звать облачные эмбеддинг-API. Voyage — только как запасной вариант за флагом, и в этом
  тикете он не реализуется.
- Не строить ретривер — это T-20. Здесь только векторизация и запись.
- Первая загрузка модели ~2 ГБ: закэшировать в томе, путь через `HF_HOME`, задокументировать
  в README-фрагменте тикета.

## Готово, когда

`ev embed` заполняет `chunks.embedding` для всего корпуса на машине без единого API-ключа,
повторный прогон отрабатывает из кэша, время индексации зафиксировано в отчёте тикета.
