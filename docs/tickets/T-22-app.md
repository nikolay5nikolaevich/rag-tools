# T-22 — Подключить живое приложение

**Статус:** выполнено 12.09.2026, ожидает приёмки. **Зависимость:** T-21.
**Результат:** вопрос в браузере проходит через настоящий поиск и ответ, источник открывается,
отзыв сохраняется. Итоговый эксперимент для запуска приложения не нужен.

Что сделать:

- Реализовать эндпоинты [CONTRACTS.md §8](../CONTRACTS.md) в `backend/ergovault/api.py`.
  API вызывает `search.py` и `answering.py`; SQL и журнал запросов остаются в `db.py`.
  Каталог и вопросы о языке/дате/типе используют метаданные `Source`, не только чанки.
- Записывать запросы и ошибки генерации в `query_log`. Возвращать его ID как `meta.query_id`;
  по нему сохранять отзыв. Опциональный текст отзыва хранить в nullable-поле, добавленном
  отдельной SQL-миграцией; одновременно обновить §5 контракта.
- Синхронизировать HTTP-схемы с `frontend/src/api/types.ts`. Для `/api/eval/summary` определить
  одну небольшую схему с состоянием «прогонов нет» и результатами; T-30 наполнит её.
- Подключить существующий фронтенд, отключить моки в обычном запуске. Обработать ожидание,
  недоступность сервиса, отказ и источник без URL. Настроить CORS для адреса фронта.
- Описать воспроизводимый локальный запуск. Использовать существующий Uvicorn;
  новый CLI-пакет, контейнер-заглушка и обязательная контейнеризация API не нужны.

Готово, когда:

- Проходит сценарий «вопрос → ответ → раскрытие конкретной цитаты → сохранение отзыва»
  на живом API; также проверены отказ и вопрос о доказательствах окупаемости.
- Успех и ошибка генерации записаны в журнал; наружу выходят ошибки §8 без traceback.
- Публичный инстанс отклоняет параметр `profile`; закрытые источники недоступны через
  поиск, каталог и прямой URL чанка. Фильтрация выполняется в SQL.
- `/healthz` сообщает состояние и счётчики без тяжёлой обработки. Экран качества при
  отсутствии результатов показывает это явно; проценты уверенности не появляются.

Проверки: контрактные тесты API и один набор браузерных сценариев на существующем Playwright.
