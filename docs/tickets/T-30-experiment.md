# T-30 — Итоговый эксперимент: четыре варианта

**Зависит от:** T-20, T-21, T-22, T-23. **Читать:** спека раздел 7.

Одни и те же вопросы, одни и те же условия, четыре варианта:
1. модель без поиска (нижняя граница);
2. модель с полнотекстовым поиском;
3. модель с выбранным RAG-поиском;
4. **весь корпус в контексте, без поиска** — обязательный сильный baseline.

Вариант 4 не срезать: ~70–90 тыс. токенов корпуса влезают в окно целиком. Для него включить
prompt caching, иначе сравнение по стоимости нечестно не в его пользу. Оба исхода — результат:
если long-context не хуже, честный вывод «на корпусе такого размера RAG оправдан стоимостью и
латентностью, а не точностью», и он идёт в отчёт как есть.

Измерения: recall@5, подтверждённость (судья + его согласие), полнота, корректный отказ,
корректное схлопывание зависимых источников, время и стоимость на ответ.

**Как измеряется стоимость при работе по подписке.** Прогон идёт через `EV_LLM_BACKEND=cli`,
и `total_cost_usd` от CLI в отчёт не идёт: в нём сидит ~17k токенов служебного промпта
Claude Code (см. T-15). В таблицу пишется `billed_cost_usd` — расчёт по публичному прайсу от
наших собственных токенов. В отчёте это оговаривается прямо: стоимость расчётная, а не по
счёту; оверхед одинаков во всех четырёх вариантах, поэтому сравнение между ними корректно,
а абсолютные значения — нижняя оценка.

Если к этому моменту появится платный ключ, прогнать вариант 3 и вариант 4 дополнительно на
`EV_LLM_BACKEND=api` и сверить расчётную стоимость с фактической. Это дешёвая проверка
(корпус крошечный) и она снимает главную оговорку отчёта.

Holdout (10 вопросов) открывается здесь **один раз**. Повторные прогоны на части вопросов —
для оценки разброса. Сохранить и удачные, и неудачные примеры.

## Приёмка: чем проверяется, что готово

| Проверка | Ожидание |
|---|---|
| Четыре варианта | без поиска; FTS; выбранный RAG; **весь корпус в контексте** — последний не срезан |
| Условия | одинаковые во всех вариантах до последнего параметра, кроме способа подачи контекста |
| Prompt caching для baseline | включён — иначе сравнение по стоимости нечестно не в его пользу |
| Holdout | открыт ровно один раз, здесь |
| Стоимость | `billed_cost_usd` по прайсу; `total_cost_usd` из CLI в таблицу не идёт |
| Оговорка о методе | стоимость расчётная, оверхед CLI одинаков во всех вариантах, абсолютные цифры — нижняя оценка |
| Вывод при ничьей | если long-context не хуже — так и написано: RAG оправдан стоимостью и латентностью, а не точностью |

Строки таблицы — условия закрытия тикета. Разошлось с реальностью — эскалация
тех-лиду с конкретными файлами, а не правка ожидаемого под факт.
