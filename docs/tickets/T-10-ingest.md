# T-10 — Ingest: парсинг корпуса, чанкинг, метаданные

**Пакет:** `backend/ergovault/ingest/` — только он. Чужие пакеты не трогать.
**Читать перед стартом:** `docs/CONTRACTS.md` §1–4 (нормативно), `docs/PLAN.md`.
**Зависит от:** T-00 (модели в `ergovault/models.py`), T-02 (корпус в `corpus/v1/`).

---

## Результат: что должно лежать на диске, когда тикет закрыт

| Артефакт | Что в нём |
|---|---|
| `corpus/v1/index/sources.jsonl` | 43 строки, по одной на источник, схема `Source` из §1 |
| `corpus/v1/index/chunks.jsonl` | ~500–1200 строк, схема `Chunk` из §1 |
| `corpus/v1/index/ingest_report.md` | отчёт прогона, состав ниже |
| `backend/ergovault/ingest/frontmatter.py` | разбор YAML-шапки, маппинг ключей |
| `backend/ergovault/ingest/markdown.py` | чанкинг по §3 |
| `backend/ergovault/ingest/attribution.py` | `speaker_org`, `stance`, `derived_of` |
| `backend/ergovault/ingest/cli.py` | команда `ev ingest` |
| `backend/tests/test_ingest.py` | тесты из раздела «Приёмка» |

JSONL — по одному JSON-объекту на строку, UTF-8 без экранирования кириллицы
(`ensure_ascii=False`), ключи в порядке полей модели, перевод строки `\n`.

Отчёт `ingest_report.md` содержит ровно эти разделы: число источников по `SourceType`;
число чанков, из них `atomic`; распределение длин чанков (min / медиана / max / сколько
упёрлось в лимит 4000); список источников без `speaker_org`; список источников без `url`;
список источников с `reliability_note` и откуда он взят (раздел или блок-цитата); список
непрочитанных ключей frontmatter.

## Что сделать

1. `frontmatter.py` — ключи в корпусе неоднородны: `duration` и `duration_minutes`,
   `source` и `source_video`, `raw`, `channel`, `published`, `video_number`, `status`,
   `source_note`, `playlist_url`, `industry`, `country`. Маппинг — явной таблицей.
   Неизвестный ключ идёт в отчёт, а не в модель.
   Заглушки вместо значений (`url: не указана (Telegram-стрим)`, `не предоставлен`) приводятся
   к `None` по правилу §2 — в поле не должно попасть слово «не указана» как текст.
2. `markdown.py` — чанкинг по §3. Три места, где легко ошибиться:
   - **нормализация заголовков** (§3 п.3): `## 4. Основные тезисы` и `## Основные тезисы` —
     это один и тот же раздел. Без снятия нумерации atomic-чанкинг не сработает ни на одной
     из тринадцати тезисных заметок;
   - **`reliability_note` собирается из двух форм** (§3.1): раздел «Ограничения источника»
     и блок `> Примечание по достоверности:`. Обе исключаются из тела чанков;
   - **перенос оговорки на оригинал** (§3.1): `reliability_note` из производной заметки
     копируется на источник из её `derived_of`, если у того нет своего.
3. `attribution.py` — `speaker_org`/`stance` по `corpus/v1/speaker_org.yml` (точное вхождение
   alias в `channel`, регистронезависимо), `derived_of` по `corpus/v1/derived_map.yml`.
   Оба файла уже заполнены тех-лидом. Fuzzy-матчинг запрещён.
4. `cli.py` — `ev ingest [--profile public|pilot] [--report] [--out DIR]`.

## Приёмка: чем проверяется, что готово

Команда `ev ingest --report` отрабатывает на чистой машине и печатает отчёт. Тесты в
`backend/tests/test_ingest.py` гоняются на **реальном корпусе**, не на выдуманных фикстурах:

| Проверка | Ожидание |
|---|---|
| Всего источников | ровно 43 |
| Распределение по `SourceType` | совпадает с таблицей §4 контракта: 13 / 13 / 5 / 1 / 2 / 1 / 1 / 7 |
| `derived_of` у `video-theses` | проставлен у всех 13, каждый ведёт на существующий `video-source` |
| `reliability_note` | заполнен минимум у 13 источников (12 из разделов + 2 из блоков, с учётом переноса на оригиналы) |
| `atomic`-чанки | не меньше 100 (в корпусе ~120 нумерованных тезисов) |
| Инварианты §1 | `chunk.id` уникальны; `heading_path` непустой; длины в границах 80–4000 (atomic — от 40) |
| Публичный профиль | ни один чанк не содержит текста из `raw/`; `visibility` везде `public` |
| Заглушки URL | ни в одном `Source.url` нет подстроки «не указан»/«не предоставл» |
| Идемпотентность | два прогона подряд дают побайтово одинаковые `sources.jsonl` и `chunks.jsonl` |

Числа выше — не пожелания, а условия закрытия тикета. Если реальность разошлась с ними,
это либо баг реализации, либо ошибка в контракте: во втором случае — эскалация тех-лиду
с конкретными файлами, а не тихая правка ожидаемого числа под факт.

## Границы

- Не подключаться к БД, не считать эмбеддинги, не звать сеть. Ingest — чистая функция от файлов.
- Не «улучшать» текст корпуса: не переписывать, не исправлять опечатки, не дополнять.
- Не заполнять отсутствующие метаданные догадками — `None` и строка в отчёте.
- Два источника намеренно без `speaker_org` (`channel: не указан`); это ожидаемый результат,
  а не недоработка.
