# T-22 — HTTP API и журналирование

**Пакет:** `backend/ergovault/api/`. **Зависит от:** T-21. **Читать:** `docs/CONTRACTS.md` §8, §5 (query_log).

FastAPI, эндпоинты §8 ровно в описанном виде. Каждый запрос пишется в `query_log`: вопрос,
найденные фрагменты со скорами и рангами, полный `AnswerPayload`, четыре версии из §10,
латентность, стоимость, ошибка. `POST /api/feedback` проставляет `feedback` по `query_id`,
который возвращается в `meta` ответа.

Требования: `/healthz` отвечает без БД-запросов тяжелее одного count; CORS для фронта из конфига;
ошибки в формате §8; никаких трассировок наружу. Профиль берётся из конфига, а параметр запроса
`profile` разрешён **только** при `EV_PROFILE=pilot` — публичный инстанс не должен уметь
переключаться в pilot по HTTP-параметру.

Тесты: контрактные (схема ответа), запись в `query_log` при успехе и при ошибке генерации,
запрет `profile=pilot` на публичном инстансе.

## Приёмка: чем проверяется, что готово

| Проверка | Ожидание |
|---|---|
| Все эндпоинты §8 | отвечают в описанном виде; схема ответа совпадает с pydantic-моделями |
| Каждый запрос | пишет строку в `query_log` с четырьмя версиями из §10, латентностью и стоимостью |
| Ошибка генерации | тоже пишется в `query_log`, в поле `error` — а не теряется |
| `POST /api/feedback` | проставляет `feedback` по `query_id` из `meta` ответа |
| `profile=pilot` на публичном инстансе | отклоняется; параметр разрешён только при `EV_PROFILE=pilot` |
| `/healthz` | отвечает без тяжёлых запросов, отдаёт corpus_version и счётчики |
| Ошибки наружу | в формате §8, без трассировок |

Строки таблицы — условия закрытия тикета. Разошлось с реальностью — эскалация
тех-лиду с конкретными файлами, а не правка ожидаемого под факт.
