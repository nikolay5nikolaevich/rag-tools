# T-04 — Спека промптов, версия `p1`

Промпты — часть контракта, а не деталь реализации T-21/T-23. Меняются вместе с инкрементом
`EV_PROMPT_VERSION`; результаты eval, снятые на другой версии, несравнимы.
Файлы: `backend/ergovault/generation/prompts/p1_system.md`, `p1_user.md`,
`backend/ergovault/eval/prompts/judge_p1.md`.

## 1. Разделение обязанностей: что делает модель, что делает код

| Задача | Кто |
|---|---|
| Сформулировать ответ по фрагментам | модель |
| Расставить ссылки `[n]` на фрагменты | модель |
| Отличить обобщение от прямого утверждения источника | модель |
| Признать нехватку данных | модель |
| Проверить, что `[n]` существует и цитата дословна | код |
| Подставить URL | код |
| Схлопнуть источники одного `speaker_org` | код |
| Собрать блок «Ограничения» | код |

Правило, определяющее архитектуру: **всё, что можно проверить программно, модели не поручается.**
Ограничения не «замечаются моделью в тексте», а вычисляются из метаданных (контракт §7).

## 2. Системный промпт генератора (`p1_system.md`)

Роль: помощник по исследованию международных выставок. Отвечает **только** по переданным
фрагментам, на русском языке.

Обязательные положения:

1. Каждое существенное утверждение сопровождается ссылкой `[n]` на номер переданного фрагмента.
   Утверждение без опоры на фрагмент не пишется вовсе — ни как «общеизвестно», ни как совет.
2. Если ответ является обобщением нескольких фрагментов, а не прямым утверждением источника,
   это обозначается словами в тексте.
3. Если переданные фрагменты не покрывают вопрос — ответ начинается с прямого признания, чего
   именно нет в материалах. Правдоподобные догадки, оценки «по опыту» и округления запрещены.
   Отказ — нормальный, полноценный ответ, а не сбой.
4. Цифры и формулировки переносятся из фрагментов дословно; пересчёт, усреднение и приведение
   к «круглым» значениям запрещены.
5. URL не пишутся никогда. Ссылки на источники расставляет программа.
6. Проценты уверенности, оценки достоверности в баллах и метафоры вроде «скорее всего»
   не используются.
7. Тон — деловой, без маркетинга и воодушевления. Читатель — сотрудник, готовящий выставку.

Формат вывода — JSON: `{"answer_markdown": str, "cited": [int], "refused": bool}`.
`cited` — номера фактически использованных фрагментов. Всё остальное поле `AnswerPayload`
заполняет код.

## 3. Пользовательский промпт (`p1_user.md`)

```
Вопрос: {question}

Фрагменты материалов:
[1] Источник: {source_title} | Тип: {source_type} | Раздел: {heading_path}
{text}

[2] ...
```

**В промпт не попадают:** URL, `speaker_org`, `stance`, `reliability_note`, `derived`.
Это не экономия токенов: метаданные атрибуции обрабатываются кодом, и модель не должна иметь
возможности ни сослаться на них, ни пересказать их своими словами.

## 4. Промпт судьи (`judge_p1.md`, T-23)

Модель судьи — `claude-sonnet-5`, **другая** и с другим промптом, чем генератор: судья,
совпадающий с генератором, оценивает сам себя.

Вход: одно утверждение из ответа + один фрагмент.
Выход: `{"verdict": "supported" | "partially" | "not_supported", "reason": str}`.

- `supported` — фрагмент прямо содержит утверждение;
- `partially` — содержит близкое, но с расхождением в числе, условии или субъекте;
- `not_supported` — не содержит.

Судья не оценивает полезность, стиль и полноту ответа — только наличие опоры.
Температура 0. Согласие судьи с ручной разметкой (40–50 пар) публикуется рядом с любой
цифрой подтверждённости — без него цифра не имеет смысла.

## 5. Промпт long-context baseline (T-30)

Тот же системный промпт `p1_system.md`, но вместо выборки фрагментов — **весь публичный корпус**
(~70–90 тыс. токенов) с той же нумерацией блоков. Prompt caching на корпус обязателен, иначе
сравнение по стоимости нечестно не в пользу baseline. Условия, кроме способа подачи контекста,
должны совпадать с вариантом RAG до последнего параметра.

## 6. Формулировки блока «Ограничения» (шаблоны кода, не модели)

| kind | Текст |
|---|---|
| `single_org` | «Все подтверждения происходят из материалов одного источника — {org}. Независимого подтверждения в корпусе нет.» |
| `provider_stance` | «Среди источников есть организатор коллективного участия ({org}) — сторона, заинтересованная в участии в выставках.» |
| `reliability_note` | «{source_title}: {reliability_note}» |
| `derived_only` | «Ответ опирается только на производные заметки (пересказы), первичные материалы не процитированы.» |
| `no_data` | «В материалах нет данных по этому вопросу. Не хватает: {что именно}.» |

Формулировки фиксированы: пользователь должен узнавать одну и ту же оговорку и не гадать,
означает ли новая формулировка новое обстоятельство.
