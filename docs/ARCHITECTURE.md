# ErgoVault RAG: устройство и следующие задачи

Сервис отвечает на вопросы по фиксированному корпусу из 43 заметок и показывает
проверяемые цитаты. Подготовка, поиск, ответ и приложение работают целиком: вопрос из
браузера проходит через настоящий поиск и генерацию, источник открывается, отзыв
сохраняется. Моки msw остались только для демонстрации экранов без бэкенда.

```text
Подготовка: cli → indexing → ingest/chunking → db → embeddings → db
Вопрос:    api → search → answering → db + embeddings → llm → проверка цитат → query_log
```

| Модуль | Назначение |
|---|---|
| `ingest.py`, `chunking.py` | Чтение Markdown, атрибуция, нарезка, JSONL |
| `embeddings.py` | Локальная модель для документов и вопросов |
| `indexing.py` | Подготовка базы и кэш векторов |
| `db.py` | SQL, миграции, загрузка и фильтр видимости |
| `search.py` | FTS, vector, hybrid, RRF и лимит чанков на источник |
| `llm/` | Доступ к Claude через CLI или API |
| `answering.py`, `prompts/` | Промпт, вызов модели, проверка ссылок и цитат, ограничения |
| `api.py` | HTTP-эндпоинты §8: разбор запроса, журнал, коды ошибок |
| `eval/` | Вопросы, прогоны, метрики, сравнение четырёх подходов и судья |
| `cli.py` | Только команды и вывод ошибок |
| `models.py`, `settings.py` | Форматы данных и настройки |

SQL находится в `db.py`; прикладной код не зависит от Typer. Поиск для приложения
и оценки один. Модель загружается лениво и переиспользуется. Исходный корпус,
идентификаторы, JSONL, схема БД, RRF и разделение public/pilot сохраняются.

Запуск из корня:

```bash
pip install -e "backend[dev,embed]"
docker compose up -d db
ev prepare
ev eval retrieval --mode hybrid --k 5

# Сравнение подходов (T-30): каждый вызов идёт в модель, прогон занимает десятки минут
ev eval compare --include-holdout        # четыре варианта, отчёт и summary.json
ev eval report eval/runs/<файл>.jsonl    # пересобрать отчёт без вызовов модели
ev eval probe                            # холодный/тёплый вызов, кэш, служебные токены
ev eval judge-pairs eval/runs/<файл>.jsonl   # собрать пары для ручной разметки судьи
ev eval calibrate                        # сверить судью с разметкой (после её заполнения)

# API: отдельный терминал, из корня репозитория
uvicorn ergovault.api:app --host 127.0.0.1 --port 8000

# Фронтенд: ещё один терминал
cd frontend
npm install
npm run dev            # живой API: dev-сервер проксирует /api и /healthz на :8000
npm run dev:mock       # только сценарии msw, бэкенд не нужен
```

Первый вопрос к живому API грузит модель эмбеддингов (десятки секунд), дальше она
переиспользуется. Ответ идёт через `claude` CLI по подписке — нужен выполненный
`claude login`; ключ API не обязателен. Другой адрес фронта задаётся `EV_CORS_ORIGINS`,
другой адрес API — `EV_API_URL` (прокси) или `VITE_API_BASE_URL` (прямой запрос).

`ev prepare` применяет миграции, читает корпус, загружает JSONL и вычисляет
векторы. Отдельные этапы: `ev ingest --report`, `ev db upgrade`,
`ev db load [каталог]`, `ev embed --no-write-db`. `ev --help` работает без БД
и весов. Из Python поиск вызывается как
`search(conn, question, k=8, profile="public", mode="hybrid")`.
